# 决策记录 0001：领域工具与系统核心保持分离

* 状态：Accepted
* 类型：Product
* 决策简述：Repo Wiki 等面向具体领域的知识与工作方式按领域工具或可选插件提供，与系统核心保持分离。
* 当前修订：2026-09-22

## 当前决定

Repo Wiki 定位为代码仓库领域工具或可选插件。它可以组织代码分析结果为带源码引用、可刷新、本地保存的知识文档，也可以由官方深度集成，但其领域归属不因此改变。

系统核心承担通用的共享资产访问、持久化、权限和扩展职责；领域工具或可选插件在这些职责之上提供具体领域的知识组织和工作方式。跨 Engine 复用不决定领域工具是否属于系统核心。

## 理由

Repo Wiki 的价值来自代码仓库这一特定领域；若把它放入系统核心，核心契约就会承担仓库知识组织的专用假设。

保持分离可以让领域工具复用共享能力，并保留按需选择其他知识工具的空间。代价是需要把领域能力作为扩展来选择和集成，这一取舍用于保持系统核心的共同边界。

## 不采用

- 不把 Repo Wiki 做成所有用户必须启用的系统核心。
- 不要求所有知识、资料或研究场景采用仓库 Wiki 的组织方式。
- 不因为插件由官方提供或与桌面深度集成，就把它重新定义为核心能力。
- 不要求索引、检索、来源引用和变化检测全部内置或始终启用。
