# 决策记录 0004：任务业务收尾与实际执行状态分离

* 状态：Accepted
* 类型：Architecture
* 决策简述：允许用户显式放弃后续协调并对任务管理收尾或归档，同时保留未知执行、残留风险、资源占用限制和后续对账责任。
* 当前修订：2026-09-22

## 当前决定

任务的业务收尾与实际执行事实分别记录。用户显式选择放弃后续协调后，即使仍有无法确认的执行，产品也可以完成任务的管理收尾或归档；未知执行仍然未知，不能因此改为已停止、已成功或已回滚。

放弃协调时，产品冻结后续派发，并撤销产品能够撤销的后续授权。该动作不承诺撤销远程在途操作已取得的实际权限，也不证明外部进程已经停止。产品继续保留未知执行、未决投递、已发生副作用、残留风险及资源占用限制，并允许后续证据对账。

任务收尾或归档不能成为资源释放的证明。可能仍被执行占用的资源须独立校验，不能仅凭任务已收尾就重新授予冲突写权限。数据删除不得抹掉仍然有效的风险和占用约束证据；生命周期和保留方式由关联领域及架构文档定义。

本决策接受上述行为语义，不批准具体状态名称、字段、存储结构或 Session 跨 Task 关系；这些建模方案仍按各自文档中的提案状态评审。既有 Session 与 Engine 的归属继续遵循决策 0003。

## 理由

远程断线或原生 Engine 无法查询时，产品可能长期无法获得停止证据。要求用户将此类任务永久留在等待状态，会把无法消除的执行不确定性转化为持续的任务管理负担。

分离业务收尾与执行事实，允许用户结束协调责任，同时如实保留无法确认的后果。代价是产品需要持续保存残留风险及对账线索，并在重新授权资源时独立检查占用约束，不能只依据任务列表中的收尾状态作判断。

## 不采用

- 不要求所有未知执行都得到确认后，用户才可以显式放弃协调并管理收尾或归档。
- 不将放弃协调、收尾或归档映射为实际执行已停止，也不承诺副作用已经撤销。
- 不因任务已收尾而自动释放可能仍被占用的资源或重新授予冲突写权限。
- 不通过删除任务记录消除仍有效的风险或占用约束证据。
