# 运行与信任边界

目的与范围：确定执行位置、状态持有者、故障恢复和安全约束，为实现与故障注入测试提供依据。

设计状态：实现方案为 Proposed；本轮 Session 与 Task 的长期关系及首版策略仍为 Proposed；业务收尾与执行事实分离遵循 [ADR 0004](../decisions/0004-task-closure-is-distinct-from-execution-state.md)。实现与验证状态：当前无 Runtime、Engine 接入或业务测试，证据基线见[架构入口](README.md)。以下是设计约束及待执行验证，不是已通过测试的行为。

关联文档：[模块边界](README.md#arc-01组织与依赖)、[领域生命周期](../domain/lifecycle-and-ownership.md)、[Engine 契约](../specs/engine-adapter.md)、[协作契约](../specs/cross-engine-collaboration.md)、[共享能力](../specs/shared-capabilities.md)、[ADR 0002](../decisions/0002-engine-native-and-product-shared-tools-are-distinct.md)、[ADR 0003](../decisions/0003-cross-engine-collaboration-is-task-scoped.md)。

## RT-01：运行所有权与持久化方案

首选 Host 作为产品权威状态唯一写入入口；Shell 只缓存可重建投影。Host 管理自己启动的子进程及其退出证据，远程执行器管理远端进程；外部已存在的 Engine 服务只按其原生公开能力管理，不因连接而取得进程所有权。关闭 UI 与停止 Host 分开；首选 UI 关闭后 Host 可继续运行，需在退出交互显示仍运行的任务和审批，不得把窗口关闭解释为同意审批或终止确认。是否采用常驻独立 Host 仍待批准。

Task 取消或收尾只冻结产品派发并分别请求停止；进程级操作仍须按 Host、远程执行器或其他明确所有者的影响范围处理，不能因 Task 取消就销毁可能被其他业务使用的 Engine 进程。

产品存储持久化任务定义、参与者身份与职责、Session 身份及其 Engine 绑定、每次业务使用关联、授权决定、待投递输入及带请求标识的派发记录、已观测执行事实、产物版本与来源。Engine 保存自己的原生私有会话；产品只保存必要原生定位标识及恢复条件，并保存能够核对产品关联的证据。UI 缓存和日志不能覆盖权威状态。具体状态及所有权以 [LIFE-02](../domain/lifecycle-and-ownership.md#life-02-状态及完成判据proposed) 为准，不另外维护一套状态机。

Host 先持久化收件、排队记录和派发意图，再调用执行方；调用前按 [LIFE-ADMISSION](../domain/lifecycle-and-ownership.md#life-admission-业务接纳资格proposed) 校验 Task 生命周期及冻结状态、参与者身份与执行资格、目标 Session 的本次使用资格、Engine／Adapter 能力、授权和执行环境。Session 打开、连接可用或恢复成功都不授予业务执行权。收到原生 Engine 或受控执行宿主的接纳证据后，按 [LIFE-INPUT](../domain/lifecycle-and-ownership.md#life-input-输入与-execution-的边界) 为新执行输入建立 Execution，或将介入输入关联已有 Execution，并持久化证据；即使尚未接纳，也保留原始 Task、参与者、Session、目标和投递证据。派发后回执丢失时标记接纳未知，保留输入记录，不伪造 Execution 已接纳或任务已核实结束；用户显式放弃协调与归档按 [LIFE-03](../domain/lifecycle-and-ownership.md#life-03-取消停止与副作用) 处理，不能据此改写执行事实。数据库提交和外部执行不构成原子事务，崩溃可能落在“已执行、未记账”窗口。恢复时对账原生执行身份、查询或重放已记录事件；缺少确认则保留结果未知，不自动重投。首选事务性本地存储与有界事件记录，不预设数据库产品，不为完整事件溯源重建所有私有上下文。

产品记录需要为每个输入和 Execution 固定保存 Task、参与者、Session、产品请求、原生执行和来源证据，记录事件来源、原生身份、接收时间与有序范围；后续 Session 使用不能覆盖已形成的历史关联，不能由 Session 当前正在服务的 Task 推导旧事件归属。迟到事件、审批答复、工具结果、用量、Artifact 和错误按原始输入／Execution 关联归档；UI 切换任务、Session 恢复、Host 重启或未来使用关系变化都不能改写归属，无法可靠关联时标记未知并进入对账。协议顺序和去重要求由[Engine 规格](../specs/engine-adapter.md)唯一规定。授权含作用域与有效期，恢复不延续过期授权。首版新的独立 Task 首次需要业务会话时默认创建新的参与者和 Session；尝试在另一 Task 使用既有 Session 必须拒绝，不能静默重绑或继承旧授权。用户放弃协调后，Host 继续持久化未知投递、执行证据及资源占用风险；重启不得恢复已撤销授权或自动启动新业务，迟到证据仍可对账。归档不能自动释放可能仍被未知执行使用的资源，业务收尾也不撤销已发生副作用；具体放弃及后续处置条件以 LIFE-03 为准。归档、删除及原生保留的关系见领域文档；删除产品记录不等于远程文件、原生 Session、风险记录或外部副作用被删除。

历史读取、会话恢复、业务接纳、任务收尾和资源释放由不同责任分别完成。首版同一 Session 只允许一个明确参与者驱动业务执行，并沿用单 Session 串行执行策略；同一 Task 内多轮工作可以继续原 Session，同一 Task 内多个参与者仍可使用多个独立 Session 协作，同一参与者也可按需使用多个同 Engine Session。首版不实现跨 Task Session 复用，也不为未来方向预先引入会话池、分布式锁或新的中间件；未来准入方向集中见 [DOM-05](../domain/README.md#dom-05-未来跨-task-串行复用条件proposed)。

## RT-02：关键运行场景

| 场景与发起方 | 状态拥有者与执行方 | 结果确认与失败处理 | 后续验证输入与判据 |
| --- | --- | --- | --- |
| 用户发起任务，Engine 调用工具 | Host 先按 Task、参与者、Session 的本次使用关联接纳，再经 Adapter 提交；Engine 拥有本轮执行与原生工具状态；共享执行器拥有共享工具运行事实 | 工具执行器确认工具结果，Adapter 记录 Engine 本轮结果；Execution 固定关联原始 Task／参与者／Session；整合者提交任务验收，不能由文本结束自动通过 | 注入工具失败与正常轮次完成，任务不得直接变为验收通过；能追踪每次工具来源和产品关联 |
| 同一 Task 多轮继续，随后创建新的独立 Task | 同一 Task 可复查资格后继续原 Session；新 Task 首次业务接纳默认创建新的参与者和 Session；Engine 仍只拥有自己的原生状态 | 每次输入和 Execution 固定保存 Task、参与者、Session、请求及来源证据；新 Task 不继承旧 Session 的使用资格或上下文披露范围 | 连续多轮输入不因一次完成强制新 Task；新 Task 不静默复用旧 Session，历史关联保持不变 |
| 请求在 Task B 使用 Task A 的既有 Session | Host 检查 B 的生命周期、参与者、授权、Session 使用资格和 Engine／Adapter 能力；首版明确拒绝跨 Task 既有 Session 使用 | 不改绑 A 的历史，不伪造恢复成功；提供为 B 创建新 Session 并只传递获准材料的路径 | 尝试重连、恢复或重新配置工具权限均不能绕过拒绝；Session 可用不等于业务接纳成功 |
| 两个不同 Engine 并行后整合 | Host 协调分工与资源授权，各 Engine 拥有独立 Session；同一 Task 可有多个参与者和 Session；指定整合者处理产物 | 资源协调器授予访问或隔离工作副本；整合者比较版本/差异并接受结果；冲突阻止覆盖；每个 Execution 归属明确 | 两者写同一基线文件，第二写入必须被排队、拒绝或隔离；整合冲突可见，不静默选择最后写入 |
| Agent 请求审批，用户拒绝或退出 | 原生工具审批由 Engine 执行边界持有；共享工具审批由共享执行器持有；Host 记录请求和用户决定 | 拒绝应送回实际执行方；只有执行方确认才能认为拒绝已生效。退出保持等待或按公开策略过期拒绝；不自动批准 | 审批显示后关闭 UI 或拒绝，验证工具没有因 UI 消失获准；丢失拒绝回执时显示未确认 |
| UI 关闭、Host 重启、Engine 进程退出 | UI 无权威执行状态；Host 重启从产品存储恢复；进程监督者记录已拥有进程的退出 | Host 对账未完成执行；Engine 退出不自动证明外部子进程或外部请求已停止。不能恢复时保留历史并提示新建 Session | 在派发前后与回执持久化前分别终止 Host，检查无静默重投；退出 Engine 后残留子进程必须可见或标明不可确认 |
| 远程断线后重连，结果未知 | 远端仍可能执行；Host 持有最后确认事实和断线观测 | 连接恢复后查询原生执行或按游标重放，核对身份与版本；不能查询时维持未知，允许按 LIFE-03 显式放弃协调；已放弃任务仍接收迟到证据 | 执行完成但响应丢失时重连，确认不会凭断线自动重做有副作用输入；查询/重放可重试但不重复业务执行 |
| 用户切换到另一个 Task 后收到旧执行结果 | Host 按原始输入／Execution 的不可变关联归档迟到事件；UI 当前 Task 只影响展示，不影响历史归属 | 迟到事件、审批答复、工具结果、用量、Artifact 和错误仍归原 Task／参与者／Execution；无法关联时进入对账 | 切换 UI、恢复 Session 或 Host 重启后注入迟到结果，不能将其归给当前 Task，也不能自动重开原 Task |
| 用户取消，文件或外部系统已变化 | Host 接收取消并停止新增派发，逐项请求 Engine/执行器中断；每个执行方确认自身范围 | 按 [LIFE-03](../domain/lifecycle-and-ownership.md#life-03-取消停止与副作用)汇总已停止、仍运行及未知；保留已产生差异和外部结果，撤销另行授权 | 一项已停止、一项离线、文件已改时，任务不得显示全部停止或已回滚；界面列出未知项和副作用 |

部分失败由 Task 策略决定继续独立分支、等待替代输入、有限重试或终止依赖分支。策略和整合者必须在派发前明确；Host 不借“恢复”无限创建重试。新的执行与先前执行保留关联及不同身份，安全重试条件见协作规格。

## RT-03：信任边界与强制能力

| 输入或边界 | 产品控制 | 不能据此宣称的保证 |
| --- | --- | --- |
| 不可信仓库文件、README、网页、工具返回内容 | 记录来源，作为任务资料传入；其文本不能变成 Host 授权；敏感外发、扩展加载和执行需要独立授权 | 提示词可以完全抵抗注入，或读一个仓库就授权执行其脚本 |
| 插件、Hooks、UI 扩展与外部进程 | 加载前声明来源与请求能力；受限接口传递资源引用；运行身份和权限可审计 | 插件与 Host 同进程时具有强隔离；Hooks 可以绕过实际执行方审批 |
| 文件、Terminal、Git、Browser | 属于 Task 的业务调用／执行入口校验 Task、Session、参与者、环境、资源、操作与有效授权；直接用户操作按其来源和自身授权记录；共享可变资源按规格协调 | Session 曾经获准使用资源，不代表新 Task 继承授权；工作目录、Git worktree、审批 UI 或提示词也不是一套完整安全沙箱 |
| 原生工具直达 OS/网络 | Adapter 公开控制范围与观测缺口；按 Engine 和宿主支持配置限制 | 产品能拦截所有绕过共享工具的调用、所有子进程或外部服务 |
| 远程执行与模型供应商 | 验证远端身份，限定传输材料，显式展示执行和数据离机范围 | 本地优先等于模型离线、远端受本地 OS sandbox 约束 |

隔离依赖真实宿主机制，例如操作系统用户权限、容器约束或 Engine 已公开的限制；是否存在及有效必须针对部署测试。缺少实际强制能力时，产品应显示限制并允许拒绝该组合；不得悄悄提高权限使任务“成功”。工作副本或 worktree 用于并发与结果整合，安全价值仅限其真实机制。

## RT-04：凭据、披露与诊断

首选凭据置于操作系统凭据设施或执行环境的原生凭据存储，产品数据只存引用。具体设施尚未选型。属于 Task 的业务执行请求按 Task、Session、参与者、资源、动作、环境和期限解析最小必要凭据；直接用户操作按其来源和自身授权处理；不得将全量环境变量、浏览器资料目录、Cookie 或密钥写入任务消息。重新配置工具权限不能证明原生 Session 已忘记先前资料；未来跨 Task 复用还必须按 [DOM-05](../domain/README.md#dom-05-未来跨-task-串行复用条件proposed) 核查上下文披露范围。同一 Engine、Workspace 或用户名不能单独证明信任和披露范围兼容。远程执行若确需凭据，必须有明确远程授权与限定生命周期；原生 Engine 自有供应商认证仍由其支持边界管理。

Browser 授权到具体身份、标签或操作范围；共享标签不复制整个登录状态给 Engine。跨 Engine 消息、Handoff 和 Artifact 发布都检查读取者与目标环境；摘要也可能含机密，不因“摘要”免除披露检查。

日志默认记录身份、阶段、错误类别和来源，不记录秘密或完整提示内容；诊断导出需展示内容范围并脱敏。原生 stderr、工具输出、插件日志也视为可能含秘密；产品能控制自己的收集和导出，不能承诺清理 Engine 独立维护的所有日志。日志保留期限、脱敏失败策略和原生数据清理能力应在首次 Engine 接入时验证。

## 未决与验收边界

需批准：首版 Task／参与者／Session 业务关联与资格规则（在实现持久化、调度和稳定公共接口前）、UI 关闭后的默认 Host 存活策略、持久化技术、事件与审计保留期限、远程身份机制、首个执行宿主的实际隔离配置。缺少这些不会改变未知结果、最小授权与状态归属规则，但会阻止对应部署宣称可恢复或安全隔离。

业务收尾与执行事实分离已经确定；具体状态名称及持久化实现仍以领域提案和后续验证为准。验收须增加：放弃协调并归档后重启 Host，未知记录与资源占用风险仍存在，不自动恢复授权或派发；迟到完成证据可对账但不自动重开业务。删除 Task 前仍须独立检查原生 Session、风险记录、未知执行和必要历史关联，不能级联删除或释放受影响资源。

跨 Task Session 复用的完整机制、关联表和稳定 API 未在本轮实现或批准；未来若评估，只应验证 [DOM-05](../domain/README.md#dom-05-未来跨-task-串行复用条件proposed) 的准入方向，不得把它写成首版能力。历史读取、会话恢复、业务接纳、任务收尾和资源释放仍需分别验证；ZCode 复用调查、Engine 原生能力验证和临时原型不依赖未来关系全部定稿，也不阻塞其他开发。

本轮只检查设计能否回答上述故障场景。未来测试应使用可控 Adapter 和执行器制造断线、重复事件、审批拒绝、崩溃窗口与副作用，再以真实 Engine 检查其可观测范围；不得用模拟通过替代真实 Engine 兼容性验证。
