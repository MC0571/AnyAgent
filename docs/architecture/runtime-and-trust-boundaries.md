# 运行与信任边界

目的与范围：确定执行位置、状态持有者、故障恢复和安全约束，为实现与故障注入测试提供依据。

设计状态：Proposed；实现与验证状态：当前无 Runtime、Engine 接入或业务测试，证据基线见[架构入口](README.md)。以下是设计约束及待执行验证，不是已通过测试的行为。

## RT-01：运行所有权与持久化方案

<a id="RT-01"></a>

首选 Host 作为产品权威状态唯一写入入口；Shell 只缓存可重建投影。Host 管理自己启动的子进程及其退出证据，远程执行器管理远端进程；外部已存在的 Engine 服务只按其原生公开能力管理，不因连接而取得进程所有权。关闭 UI 与停止 Host 分开；首选 UI 关闭后 Host 可继续运行，需在退出交互显示仍运行的任务和审批，不得把窗口关闭解释为同意审批或终止确认。是否采用常驻独立 Host 仍待批准。

产品存储持久化任务定义、参与者关联、授权决定、待投递输入及带请求标识的派发记录、已观测执行事实、产物版本与来源。Engine 保存自己的私有会话；产品只保存必要原生定位标识及恢复条件。UI 缓存和日志不能覆盖权威状态。具体状态及所有权以 [LIFE-02](../domain/lifecycle-and-ownership.md#LIFE-02) 为准，不另外维护一套状态机。

Host 先持久化收件、排队记录和派发意图，再调用执行方；收到原生 Engine 或受控执行宿主的接纳证据后，按 [LIFE-INPUT](../domain/lifecycle-and-ownership.md#LIFE-INPUT) 为新执行输入建立 Execution，或将介入输入关联已有 Execution，并持久化证据。派发后回执丢失时标记接纳未知，保留输入记录并阻止 Task 进入任何终态，不伪造 Execution 已接纳。数据库提交和外部执行不构成原子事务，崩溃可能落在“已执行、未记账”窗口。恢复时对账原生执行身份、查询或重放已记录事件；缺少确认则保留结果未知，不自动重投。首选事务性本地存储与有界事件记录，不预设数据库产品，不为完整事件溯源重建所有私有上下文。

产品记录需要按 Task/Session/Execution 关联，记录事件来源、原生身份、接收时间与有序范围；协议顺序和去重要求由[Engine 规格](../specs/engine-adapter.md)唯一规定。授权含作用域与有效期，恢复不延续过期授权。归档、删除及原生保留的关系见领域文档；删除产品记录不等于远程文件、原生 Session 或外部副作用被删除。

## RT-02：关键运行场景

<a id="RT-02"></a>

| 场景与发起方 | 状态拥有者与执行方 | 结果确认与失败处理 | 后续验证输入与判据 |
| --- | --- | --- | --- |
| 用户发起任务，Engine 调用工具 | Host 接纳任务并经 Adapter 提交；Engine 拥有本轮执行与原生工具状态；共享执行器拥有共享工具运行事实 | 工具执行器确认工具结果，Adapter 记录 Engine 本轮结果；整合者提交任务验收，不能由文本结束自动通过 | 注入工具失败与正常轮次完成，任务不得直接变为验收通过；能追踪每次工具来源 |
| 两个不同 Engine 并行后整合 | Host 协调分工与资源授权，各 Engine 拥有独立 Session；指定整合者处理产物 | 资源协调器授予访问或隔离工作副本；整合者比较版本/差异并接受结果；冲突阻止覆盖 | 两者写同一基线文件，第二写入必须被排队、拒绝或隔离；整合冲突可见，不静默选择最后写入 |
| Agent 请求审批，用户拒绝或退出 | 原生工具审批由 Engine 执行边界持有；共享工具审批由共享执行器持有；Host 记录请求和用户决定 | 拒绝应送回实际执行方；只有执行方确认才能认为拒绝已生效。退出保持等待或按公开策略过期拒绝；不自动批准 | 审批显示后关闭 UI 或拒绝，验证工具没有因 UI 消失获准；丢失拒绝回执时显示未确认 |
| UI 关闭、Host 重启、Engine 进程退出 | UI 无权威执行状态；Host 重启从产品存储恢复；进程监督者记录已拥有进程的退出 | Host 对账未完成执行；Engine 退出不自动证明外部子进程或外部请求已停止。不能恢复时保留历史并提示新建 Session | 在派发前后与回执持久化前分别终止 Host，检查无静默重投；退出 Engine 后残留子进程必须可见或标明不可确认 |
| 远程断线后重连，结果未知 | 远端仍可能执行；Host 持有最后确认事实和断线观测 | 连接恢复后查询原生执行或按游标重放，核对身份与版本；不能查询时维持未知，要求明确处置 | 执行完成但响应丢失时重连，确认不会凭断线自动重做有副作用输入；查询/重放可重试但不重复业务执行 |
| 用户取消，文件或外部系统已变化 | Host 接收取消并停止新增派发，逐项请求 Engine/执行器中断；每个执行方确认自身范围 | 按 [LIFE-03](../domain/lifecycle-and-ownership.md#LIFE-03)汇总已停止、仍运行及未知；保留已产生差异和外部结果，撤销另行授权 | 一项已停止、一项离线、文件已改时，任务不得显示全部停止或已回滚；界面列出未知项和副作用 |

部分失败由 Task 策略决定继续独立分支、等待替代输入、有限重试或终止依赖分支。策略和整合者必须在派发前明确；Host 不借“恢复”无限创建重试。新的执行与先前执行保留关联及不同身份，安全重试条件见协作规格。

## RT-03：信任边界与强制能力

<a id="RT-03"></a>

| 输入或边界 | 产品控制 | 不能据此宣称的保证 |
| --- | --- | --- |
| 不可信仓库文件、README、网页、工具返回内容 | 记录来源，作为任务资料传入；其文本不能变成 Host 授权；敏感外发、扩展加载和执行需要独立授权 | 提示词可以完全抵抗注入，或读一个仓库就授权执行其脚本 |
| 插件、Hooks、UI 扩展与外部进程 | 加载前声明来源与请求能力；受限接口传递资源引用；运行身份和权限可审计 | 插件与 Host 同进程时具有强隔离；Hooks 可以绕过实际执行方审批 |
| 文件、Terminal、Git、Browser | 执行入口校验环境、参与者、资源、操作与有效授权；共享可变资源按规格协调 | 工作目录、Git worktree、审批 UI 或提示词是一套完整安全沙箱 |
| 原生工具直达 OS/网络 | Adapter 公开控制范围与观测缺口；按 Engine 和宿主支持配置限制 | 产品能拦截所有绕过共享工具的调用、所有子进程或外部服务 |
| 远程执行与模型供应商 | 验证远端身份，限定传输材料，显式展示执行和数据离机范围 | 本地优先等于模型离线、远端受本地 OS sandbox 约束 |

隔离依赖真实宿主机制，例如操作系统用户权限、容器约束或 Engine 已公开的限制；是否存在及有效必须针对部署测试。缺少实际强制能力时，产品应显示限制并允许拒绝该组合；不得悄悄提高权限使任务“成功”。工作副本或 worktree 用于并发与结果整合，安全价值仅限其真实机制。

## RT-04：凭据、披露与诊断

<a id="RT-04"></a>

首选凭据置于操作系统凭据设施或执行环境的原生凭据存储，产品数据只存引用。具体设施尚未选型。请求执行时按资源、参与者、动作、环境和期限解析最小必要凭据；不得将全量环境变量、浏览器资料目录、Cookie 或密钥写入任务消息。远程执行若确需凭据，必须有明确远程授权与限定生命周期；原生 Engine 自有供应商认证仍由其支持边界管理。

Browser 授权到具体身份、标签或操作范围；共享标签不复制整个登录状态给 Engine。跨 Engine 消息、Handoff 和 Artifact 发布都检查读取者与目标环境；摘要也可能含机密，不因“摘要”免除披露检查。

日志默认记录身份、阶段、错误类别和来源，不记录秘密或完整提示内容；诊断导出需展示内容范围并脱敏。原生 stderr、工具输出、插件日志也视为可能含秘密；产品能控制自己的收集和导出，不能承诺清理 Engine 独立维护的所有日志。日志保留期限、脱敏失败策略和原生数据清理能力应在首次 Engine 接入时验证。

## 未决与验收边界

需批准：UI 关闭后的默认 Host 存活策略、持久化技术、事件与审计保留期限、远程身份机制、首个执行宿主的实际隔离配置。缺少这些不会改变未知结果、最小授权与状态归属规则，但会阻止对应部署宣称可恢复或安全隔离。

本轮只检查设计能否回答上述故障场景。未来测试应使用可控 Adapter 和执行器制造断线、重复事件、审批拒绝、崩溃窗口与副作用，再以真实 Engine 检查其可观测范围；不得用模拟通过替代真实 Engine 兼容性验证。
