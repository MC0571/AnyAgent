# 共享能力接入契约

目的与范围：约束可复用产品资产、共享工具及扩展的身份、授权和生命周期，不为每个工具定义完整 API。

设计状态：Proposed（2026-09-22）；工具归属继承 [ADR 0002](../decisions/0002-engine-native-and-product-shared-tools-are-distinct.md)，领域扩展继承 [ADR 0001](../decisions/0001-domain-tools-are-optional-plugins.md)。实现与验证状态：当前无共享能力实现或 SC 测试；以下为未来验收条件。术语与状态归属见[领域模型](../domain/README.md)、[生命周期](../domain/lifecycle-and-ownership.md)；并发整合行为只在[协作契约](cross-engine-collaboration.md#COL-06)定义；实际执行和隔离方案见[运行与信任边界](../architecture/runtime-and-trust-boundaries.md)。

## 能力组合与工具归属

<a id="CAP-01"></a>
**CAP-01 条件组合。** 产品能力提供方声明操作、资源范围、执行位置、版本、权限要求及可撤销程度。宿主将其与 Engine、Adapter、Workspace 环境、配置及授权组合校验，按 [ENG-02](engine-adapter.md#ENG-02) 呈现支持性与可用性。Local、SSH、WSL、Docker 是目标环境维度，不是当前已验证支持列表。远程执行前需明确工具在哪一侧运行、路径如何解析、结果回传到哪里及网络是否可达；本地 MCP 地址或本地路径不能默认在远程可用。条件不符时拒绝或展示明确降级，不能自动移动凭据、切换执行宿主或提升权限。

<a id="CAP-02"></a>
**CAP-02 资源身份与范围。** 属于 Task 的共享业务调用派发前须遵循 [LIFE-ADMISSION](../domain/lifecycle-and-ownership.md#LIFE-ADMISSION) 的 Task／参与者资格及冻结约束。所有共享调用携带产品资源身份、Task／参与者／Execution（如适用）、授权引用和操作范围；直接用户操作记录用户来源。路径只是定位信息，不能代替资源身份或权限。执行前校验授权仍有效，结果记录执行宿主、来源和副作用；并发授予和冲突接受遵循 COL-06。

| 能力 | 最小身份、访问范围和结果归属 |
| --- | --- |
| Workspace | 逻辑身份加环境身份；授权到目录／仓库及操作，文件定位需经执行宿主验证，不能以工作目录等同沙箱 |
| File | Workspace 内资源定位、读写操作及基线版本；写入结果归执行记录，产物引用实际版本；符号链接或路径逃逸需在实际执行边界处理 |
| Diff | 两端版本／基线及产生者；查看差异不授权应用差异，应用按目标 File 写入权限和基线校验 |
| Git | 仓库及工作副本身份；读取、修改、提交、推送等分别授权，拥有文件写权限不等于拥有远程发布权限 |
| Terminal | 宿主、终端会话和进程关联；输入与输出按授权归属记录，关闭视图不证明进程退出，命令副作用不能由退出码完整描述 |
| Browser | 浏览器配置档、标签身份及获准来源／操作；导航后重新核对适用范围，控制权与读取权可分离；结果关联标签和执行 |
| Artifact／Context | 稳定身份、版本、来源和允许披露范围；读取某 Task 不自动授权读取全部历史或其他任务知识 |

<a id="CAP-03"></a>
**CAP-03 两类工具分别负责。** 产品共享工具的配置、授权记录、执行路由和调用状态由产品持有，实际操作由声明的执行宿主完成；Adapter 仅在 Engine 支持的工具／MCP 等边界暴露获准子集。Engine-native Tools 的配置、执行、权限强制和私有状态由 Engine／其宿主负责，产品仅控制已公开的设置和事件。相同名称不等于同一工具，UI 须显示来源与执行位置。产品的批准不能覆盖 Engine 拒绝，Engine 自有批准也不自动授权产品共享资源。原生工具绕过产品执行通道时，必须显示产品无法强制约束的范围，不宣称共享工具审计覆盖全部活动。

## Browser、凭据与扩展

<a id="CAP-04"></a>
**CAP-04 浏览器授权最小披露。** 共享 Browser 向参与者授予标签／来源范围内的动作或内容读取能力，优先通过受控操作句柄提供，不能把整个浏览器配置档或 cookie 库交给每个 Engine。新标签、导航到新来源、下载和登录态使用必须重新匹配授权；同源并不代表所有敏感内容都可披露。截图、DOM 和工具结果也可能含秘密，转交另一个 Engine 或远程环境前按接收者范围筛选。失去控制权的参与者不可继续写同一标签；用户接管时应撤销或暂停相关控制授权，并显示在途动作无法保证撤回的限制。

Browser 和 Computer Use 分开声明能力和授权。拥有 Browser 控制不意味着可截取其他应用、读系统无障碍树或注入全局键鼠；Computer Use 需要其宿主独立授权和可观察范围。共享登录状态仅能在授权的配置档及执行位置使用，不以同步体验为理由自动复制到远程宿主。

<a id="CAP-05"></a>
**CAP-05 扩展加载是授权边界。** 产品对扩展记录身份、来源、版本、能力要求及启用范围。发现或安装不等于启用；启用前验证兼容条件和权限，更新前重新比较权限变化。授权撤销后停止新的调用，已执行或在途副作用按执行证据报告。停用和卸载区分程序移除与用户资产删除，默认保留资产并说明仍运行的外部进程。未经确认的原生兼容性按待验证显示。

| 扩展方式 | 接入与生命周期要求 |
| --- | --- |
| MCP | 分清客户端、server 和执行位置；分别校验工具模式、传输、身份认证和网络可达性。MCP 本身不提供通用沙箱，也不自动授予任何工具调用权限；server 断开后在途结果可能未知 |
| Skills | 作为带来源与版本的指令／资源包读取，经 Adapter 映射给支持的 Engine；指令文本不改变系统授权，不保证不同 Harness 的装载语义相同 |
| Plugins | 显示所捆绑程序、工具和权限；外部进程须有所有者及停用策略，不能用插件配置替代 OS 隔离；版本变化后重新核验兼容和授权 |
| Hooks | 在明确事件点、超时和失败策略下执行；写入或网络副作用单独授权。首选失败时阻止依赖它的高影响动作并报告原因，不把失败吞成成功；禁止无界递归触发 |
| UI 扩展 | 通过公共产品协议和受限资产访问交互，不直接获得宿主秘密或任意执行权；宿主校验每个请求，不能相信 UI 隐藏按钮就是权限限制 |

凭据由实际凭据所有者存放；产品只向获准执行边界提供所需句柄或最小凭据材料。日志、扩展错误和诊断默认避免记录秘密；确需披露内容的操作必须符合资源授权。具体存储和传递设计见[运行与信任边界](../architecture/runtime-and-trust-boundaries.md)。

## 知识与领域插件

<a id="CAP-06"></a>
**CAP-06 资产可复用且保留来源。** 知识和 Artifact 引用必须含稳定身份、版本／内容指纹、产生者与原始来源定位、授权范围及派生关系；缺来源时明确显示缺口。索引、摘要和检索结果不能被当成原始事实，源文件变化后旧结果仍引用旧版本并可标记过期。删除源访问授权后，新检索和披露应停止；已披露给外部 Engine 的内容不能承诺被追回。产物修改形成新版本，验收记录引用精确版本。

Repo Wiki 等领域插件通过公共资产读写、权限、工具和 UI 扩展边界实现索引／检索／刷新；其仓库专用结构及算法由插件持有，Core 不依赖该插件。第二个应用可以选择其他知识组织方式或完全不装知识扩展；Reference App 的品牌、账户、计费和遥测不得作为这些公共能力的隐藏前置条件。

## 验收场景

| 标识 | 场景 | 可观察断言 |
| --- | --- | --- |
| <a id="SC-01"></a>SC-01 | 本地工具绑定远程 Workspace，但无已验证网络和路径映射 | 组合不可用或待验证；不自动导出凭据或伪称本地路径有效 |
| <a id="SC-02"></a>SC-02 | 两参与者共享登录浏览器，一方仅获某标签读取 | 未授权控制及其他标签读取被拒；转交结果遵循接收者范围 |
| <a id="SC-03"></a>SC-03 | 同名原生工具与共享工具被调用，分别拒绝授权 | UI 可区分来源及实际执行边界；一侧批准不能放行另一侧 |
| <a id="SC-04"></a>SC-04 | 插件更新增加权限、停用时工具仍运行、MCP 断线 | 更新需重新授权；新调用停止，在途结果如实显示，不宣称已回滚 |
| <a id="SC-05"></a>SC-05 | Artifact 源文件改变或授权撤销 | 旧产物保持版本来源；新读取被校验，不继续泄露已撤销资产 |
| <a id="SC-06"></a>SC-06 | 最小第二应用只接入 Core 公共能力，不安装 Repo Wiki 或品牌服务 | 能创建任务、接入测试 Engine 并访问获准资产；无 Reference App 内部导入 |
| <a id="SC-07"></a>SC-07 | 替换第三方协议库，保持适配后的能力和事件语义 | 公共契约验收保持成立；差异只由 Adapter 能力声明暴露，业务不依赖第三方类型 |
| <a id="SC-08"></a>SC-08 | Hook 超时、路径逃逸、UI 伪造权限或 Browser 转到未授权来源 | 执行边界拒绝／阻塞相关动作并记录原因；无静默放行 |

SC-06／07 需在有真实 Core 后执行依赖检查和公共契约集成测试；本轮没有实现，不能据文档链接通过推断其通过。

## 待评审与验证

公共扩展的具体签名、资源句柄撤销方式及插件执行隔离依赖后续宿主设计。首选将权限变更重新授权、共享资源范围检查和来源记录置于产品边界，避免每个 UI 重复实现；原生工具通道的实际覆盖程度须按 Engine 版本核验。MCP、Skills、Plugins、Hooks 名称在此表示接入类别，不承诺任一第三方实现兼容；本轮未选择第三方库，也未安装运行环境。
