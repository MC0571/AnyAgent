# Engine Adapter 行为契约

目的与范围：约束完整 Harness 如何接入产品，以及 UI 可以据何种证据呈现运行结果；不指定 SDK、IPC 或持久化结构。

设计状态：整体契约为 Proposed（2026-09-22）；D-101 已批准 M1 单参与者路径的近期会话、资格和归属语义，权威范围见[领域模型 DOM-02](../domain/README.md#dom-02-关联基数与身份连续性proposed)及[生命周期](../domain/lifecycle-and-ownership.md)。该批准不确定完整接口、状态词、长期关系或多参与者协作。继承 [ADR 0002](../decisions/0002-engine-native-and-product-shared-tools-are-distinct.md) 与 [ADR 0003](../decisions/0003-cross-engine-collaboration-is-task-scoped.md)，不扩大其已接受语义。实现与验证范围以当前代码、测试和运行记录为准；下列 EA 场景不单独证明通过。共享授权见[共享能力](shared-capabilities.md)，协议层次见[架构](../architecture/README.md)。

## 最小接入与能力声明

### ENG-01 最小完整接入

自研 Engine Adapter 应能声明版本和运行条件，创建绑定该 Engine 的 Session，提交一次输入，关联输入与 Execution，输出至少一种可呈现结果或明确错误，并报告会话关闭和取消请求的处理结果（可以明确不支持原生关闭／取消，而不能虚报成功）。正常完成必须有原生完成证据；没有可核实终态时只能报告未知，不能用连接关闭推断成功。恢复、运行中介入、原生审批、工具注入、用量和子 Agent 控制可以不支持，但必须明确声明。Engine 必须仍拥有自己的 Agent Loop；仅调用 Model API 生成文本不满足完整 Harness 接入，若另行构建 Loop，该运行体才作为独立 Engine 评审。

### ENG-02 条件化能力

Adapter 对每项能力报告支持性（支持／不支持／待验证）和当前可用性（可用／暂不可用／授权不足），附 Engine、Adapter 版本、执行环境、配置版本及必要原因。缺字段表示未知，不等于不支持；支持且当前不可用也不等于永久不支持。宿主在启动和条件变化时重新检查组合，UI 展示原因和可选操作。任何降级须呈现实际方式，不能通过换到更高权限环境恢复表面可用。未核实的 Engine × Workspace 组合不得标记可用。

Task 创建或授权时的能力与配置证据保留为历史快照；已有 Task 的“当前能力”和操作入口必须读取带来源与观测时间的当前 Host 探测，不得覆盖历史快照或沿用旧的可用状态。尚未探测、探测失败或条件变化使结果失效时标记未知；条件恢复后重新核验配置兼容性与本次授权，UI 刷新不能替代 Runtime 派发前的独立校验。

用于判断当前可用性的模型连接探测须使用该模型与 Provider 可接纳的请求参数；探测请求自身无效时，不得把失败解释成凭据失效。探测流被输出上限截断，或 HTTP 请求成功但上游明确报告失败时，不得标为可用。

## Session 与输入

### ENG-03 Session 操作

创建前宿主校验 Engine 可用、环境可达及必要授权；面向业务的创建和恢复同时遵循 [LIFE-ADMISSION](../domain/lifecycle-and-ownership.md#life-admission-业务接纳资格proposed)，Session 可用不替代本次请求的 Task／参与者执行资格。只读历史或对账不得借恢复隐式启动原生业务；恢复会自动续跑且无法约束时须报告限制。产品 Session 与原生身份的映射在确认后建立，创建响应丢失则保留待核实关联，不盲目重复创建。恢复只能面向原 Engine，并检查原生句柄、版本和原生存储是否仍有效。不支持恢复时 UI 保留产品历史，提供显式新建 Session 或 Handoff，不能称为“恢复成功”。关闭请求须说明是释放连接、结束原生会话还是删除原生状态；关闭连接不证明执行停止，删除不是默认副作用。

Session 终身绑定一个 Engine，但不因此把某个 Task 定义为其永久生命周期所有者。面向业务的输入必须通过产品保存并校验的使用关联同时指向 Task、参与者和目标 Session；Host／Adapter 不得信任调用者任意填写的标识。首版对新的独立 Task 默认创建新的参与者和 Session；Task B 试图使用 Task A 的既有 Session 时必须拒绝且不得静默重绑，改由新 Session 和经授权的材料传递继续。Session 恢复、连接可用或原生身份可查询，都不能替代本次业务的接纳资格。

### ENG-04 输入阶段证据

四阶段的含义由[输入生命周期](../domain/lifecycle-and-ownership.md#life-input-输入与-execution-的边界)定义；以下约束确认条件及可观察证据，并非另一套 Execution 状态机：

| 阶段 | 谁确认及前置条件 | 用户可见含义 |
| --- | --- | --- |
| 已接收 | 产品入口校验格式并记录请求标识 | 产品已收到；未承诺排队成功或 Engine 接受 |
| 已接纳 | Adapter 从 Engine 或受控执行宿主获得接纳证据；新执行输入建立 Execution，运行中介入关联现有 Execution | 执行方承担处理责任；仅在产品队列等待不算接纳 |
| 开始执行 | Adapter 获得原生开始证据，或由已核实同步调用语义证明 | Engine 已开始处理；写入套接字不足以证明 |
| 执行完成 | Adapter 获得原生终态及其结果，产品记录该证据 | 本次执行结束；不等于参与者分工完成或 Task 验收通过 |

输入在尚未接纳、尚未形成 Execution 时，也必须保留原始 Task、参与者、目标 Session、产品请求标识、投递来源及可获得的原生关联。形成 Execution 后，产品继续固定这些关联，并记录与原生执行和来源证据的对应关系；后续 Session 使用关系、UI 当前任务、Session 恢复或 Host 重启都不能改写历史归属。无法可靠关联时标记为关联未知并进入对账，不得猜测归属。

宿主在排队校验后、实际派发前再次按 [LIFE-ADMISSION](../domain/lifecycle-and-ownership.md#life-admission-业务接纳资格proposed) 核对 Task／参与者资格和冻结状态；冻结先于派发提交时拒绝交付，不创建新 Execution。派发先于冻结时保留真实证据并请求停止，不能把原生工具或外部路径声称为已受产品强制阻断。宿主必须保留接收后被拒绝的原因；排队等待不是正在执行。原生协议只提供完成证据时，可直接记录完成并注明开始时刻未知，不伪造中间事件。输入的关联标识及幂等范围见 ENG-06。

### ENG-05 排队、介入和中断

首选草案为同一 Session 一次只执行一个输入，其余按明确队列顺序等待。运行中介入只在能力和授权允许时发送；不支持时产品须让调用者明确选择下一轮排队或拒绝，交互 UI 展示策略，自动化需预先配置，未选择时拒绝。介入成功只证明原生接纳程度，不证明模型理解。受支持的运行中介入保留独立输入／消息证据，并关联当前 Execution，不创建另一个并发 Execution；下一轮排队的输入只有获得执行方接纳后才建立新 Execution。中断请求和执行停止分别记录；不支持原生中断时报告限制，仅在执行宿主明确允许且用户授权覆盖时提供终止自有进程选项，不能伪装成原生取消。任务聚合规则见[协作契约](cross-engine-collaboration.md#col-07-控制生效范围可核查)。

M1 已批准同一 Task 围绕同一目标继续多轮实现、评审和修复并沿用原 Session；继续工作不等于每条用户消息都新建 Task，且每次业务请求仍须重新校验资格。新的独立 Task 使用新参与者和新 Session，拒绝直接复用旧 Task 的 Session。一个 Session 只允许一个明确参与者驱动，并按单 Session 单 Execution 串行执行。多参与者、多 Session 或多 Harness 协作仍属 Proposed 且不在 M1 范围；Session 生命周期解耦也不绕过 Task 的业务接纳。

M1 的原生 `/compact` 是独立的 Session 维护操作，不作为普通用户输入，也不伪造 Input 或 Execution。产品对每次请求固定 Task／参与者／Session 归属并核验当前能力、授权和环境；若等待其他执行结束，实际派发前重新核验。记录原生命令的接纳、完成或未知结果及已知副作用，不能把排队或传输回执当成压缩完成。

## 事件、审批与失败

### ENG-06 关联、顺序和重连

产品可观察事件必须关联 Engine、产品 Session、Execution（如适用）、来源和事件标识；保留可获得的原生关联标识。Adapter 生成产品事件标识和流内序号时，只保证该 Adapter 实例的一个事件流顺序，重启使用新流身份；不得据到达顺序宣称跨 Engine 的全局因果顺序。分片附所属结果和分片序号；来源无法支持稳定去重时须声明这一限制。产品按稳定事件标识去重投影，重复完成不能重复发布产物或接纳任务结果。

文本增量有原生消息或分块身份时保留该身份，按 Execution 和分块呈现；没有身份时只在可证实的单一来源范围内降级聚合，不把推理、不同分块或不同 Execution 无条件拼成普通正文。最终结果与增量应协调为一次可读回答，原始事件仍可供诊断。

事件、审批答复、工具结果、用量、Artifact 和错误都必须沿用原始输入或 Execution 的 Task／参与者／Session 关联，并保留产品请求、原生执行及来源证据；不能根据 UI 当前任务或 Session 的最新使用者动态改归属。若 Adapter 无法可靠取得或保存原生执行关联，必须标记关联未知并进入对账，不得宣称支持跨 Task Session 复用能力。

重连先查询执行状态或重放可用游标；有缺口则显示缺口及最后已知证据，不补造文本、工具事件或用量。不能查询或重放时，将受影响执行保持为结果未知。接纳回执也未收到时保留未决投递记录，不虚构已接纳 Execution；未决投递同样阻止任务被宣称全部停止；按 [LIFE-03](../domain/lifecycle-and-ownership.md#life-03-取消停止与副作用) 显式放弃协调不改变该未知事实。产品请求标识只能防止同一产品记录重复入队；除非原生协议验证了幂等处理或查询明确证明未执行，响应丢失后不得自动重发可能有副作用的输入。重试应创建可追溯的新 Execution，并先核对已发生副作用。终态记录保留来源；后到的普通事件不得重开已结束执行。互相冲突的原生终态应产生诊断和人工核实项，禁止悄悄用“最后写入胜出”改成成功。

原生编辑或重试作为新的产品输入记录，只有取得原生接纳证据才建立新的 Execution；来源输入和 Execution 保留，记录修订来源，不能就地改写旧证据。原生会话回退了对话分支时，正式消息流须区分旧分支与当前分支。修订命令回执丢失时先查询原请求，结果未知不得自动重发。编辑或重试不隐含工作区文件撤销；文件撤销须单独预览、校验授权并记录实际副作用。

### ENG-07 审批与用户输入

Adapter 仅映射 Engine 公开的请求，保留请求标识、作用范围、关联执行、允许选项和有效期。产品回答前校验请求仍有效、回答者授权及 Engine 支持的语义；重复回答不得再次放行动作。用户拒绝、超时或 UI 退出不应被映射为同意；无回答时维持等待或按已声明策略拒绝，显示实际结果。批准记录只说明产品授权，必须等实际执行方确认，不能宣称底层限制已解除。用户输入请求与权限批准分开呈现，普通文本回复不自动扩大权限。

审批请求及答复还须固定其原始 Task、参与者、Session 和 Execution（如已形成）关联；切换 UI 任务或恢复 Session 不得把未决审批转交给新任务。Task 冻结或终态后的新业务审批须按 LIFE-ADMISSION 拒绝，必要的历史读取、对账和停止控制仍按原关联处理。

### ENG-08 错误及原生扩展

失败响应必须关联操作、发生层和已知副作用；至少区分：

| 结果 | 判断依据与产品行为 |
| --- | --- |
| 不支持 | 能力契约不提供该操作；禁用入口并说明替代方式 |
| 暂不可用 | 条件暂不满足；显示缺失条件，可在条件恢复后重新校验 |
| 授权不足 | 指定范围未获授权；展示所需范围，不自动提权 |
| 执行失败 | 执行方确认失败；显示错误和已发生结果，不假定无副作用 |
| 结果未知 | 缺乏足够完成或失败证据；保留核实入口，禁止自动作为成功或安全重试 |

扩展事件和命令使用 Engine 命名空间及版本，UI 只有在有对应渲染器时提供专属交互，否则显示受限提示；未知扩展不影响已知核心事件消费，但未知权限命令必须拒绝。产品协议版本不兼容时拒绝启动并说明需要的版本；Adapter 隔离第三方类型。推理、工具、原生子 Agent、用量和私有状态只映射原生公开内容，不要求导出私有上下文；缺失值保留未知，不能补零或虚构完成。错误及已知副作用也必须归档到原始 Task／参与者／Execution，不能因归档或更换 Session 使用关系而迁移。

## 契约验收

使用可控假 Engine、事件回放和持久化重启夹具验证产品语义；接入真实 Engine 时，再用固定版本验证其 Adapter 映射。前者通过不能证明某个真实 Harness 支持相同能力。

### 首版待实现验收（Proposed）

D-101 已批准的 M1 行为范围覆盖 EA-08、EA-10–EA-13 中的资格核验、同 Task 多轮、独立 Task 新建、跨 Task 拒绝和迟到事件原归属；具体实现和验证结果须核对当前代码与测试。表内其余契约细节仍为 Proposed。

| 标识 | 输入或故障注入 | 必须观察到的结果 |
| --- | --- | --- |
| EA-01 | 最小自研 Engine 提供创建、输入、结果，对关闭／取消明确回复不支持；恢复与介入不支持 | ENG-01 基本路径可用；缺失能力有明确标签，无模拟恢复 |
| EA-02 | 授权失效、环境断开、未知版本分别接入 | 能力可用性按 ENG-02 变化，不被统一折成“不支持” |
| EA-03 | 先接收、排队，再原生接纳；分别向支持及不支持 steer 的 Engine 注入运行中输入 | 阶段证据可区分；不支持时显式排队／拒绝，支持时介入关联当前 Execution 且保留独立输入证据，不增加并发执行 |
| EA-04 | 重复事件、流断线、游标缺口及相互冲突终态 | 无重复产品副作用；缺口、未知和冲突可见，无虚构全局顺序 |
| EA-05 | 输入已送达但响应丢失，原生查询也不可用 | 不自动重发；接纳或执行结果未知，核对副作用后才能显式重试 |
| EA-06 | 审批拒绝、过期、重复回答及 UI 退出 | 无默认放行，过期答案被拒，保留实际停止／等待证据 |
| EA-07 | 未提供用量、仅提供结束事件及未知扩展 | 未知值不补零，开始时间不伪造，核心消费继续且未知命令不执行 |
| EA-08 | Task 已终态但 Session 仍 open，或原生会话刚恢复；再提交新输入，同时读取历史、查询状态并接收迟到事件 | 业务请求因任务资格被拒，不产生新 Execution；获准历史读取、对账、必要停止控制及证据记录继续，不自动重开 Task 或重绑 Session |
| EA-09 | 输入已排队，冻结分别发生在派发提交前后；同时请求委派和共享工具 | 冻结前未派发的工作不交付，委派与工具同样受资格校验；已派发工作保留接纳／未知证据并请求停止，不虚报强制阻断或立即停止 |
| EA-10 | 同一 Task 连续进行实现、评审和修复，多次输入分别完成 | 每次重新校验 Task／参与者／Session 使用资格；可继续原 Session 和原 Task，不因一次 Execution 完成强制新建 Task |
| EA-11 | 新建独立 Task，旧 Task 已保留历史和 Session | 首版创建新的参与者与 Session；旧 Session、原 Task／参与者／Execution 历史保留，不静默继承原生上下文或权限 |
| EA-12 | Task B 请求直接使用 Task A 的既有 Session | 明确拒绝，不改绑旧记录、不伪造恢复；提供新 Session 及经授权材料传递路径，拒绝结果归档到 B 的请求关联 |
| EA-13 | 用户切换到 Task B 后收到 Task A 的迟到执行结果、审批答复或工具事件 | 结果仍归档到 A 的参与者／Execution／来源证据；不能按 UI 当前 Task 或 Session 最新使用者归给 B；无法关联时标未知并进入对账 |

### 未来跨 Task 串行复用准入验证（Proposed，非首版能力）

未来若评估复用，必须按[领域模型中的准入条件](../domain/README.md#dom-05-未来跨-task-串行复用条件proposed)逐项验证；本场景不是首版支持或已测试通过的声明。

| 标识 | 输入或故障注入 | 必须观察到的结果 |
| --- | --- | --- |
| EA-14 | 尝试复用既有 Session，但 Engine 身份／环境、原 Task 在途状态、新 Task 授权、上下文披露、单一驱动者或可靠关联条件任一不满足；仅重置工具权限 | 按未来准入条件拒绝复用，不把 Session 交给新 Task；提供新 Session 和获准材料路径，不将权限重置或 Task 归档当作满足条件的证据 |

## 待评审与验证
