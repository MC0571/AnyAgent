# Engine Adapter 行为契约

目的与范围：约束完整 Harness 如何接入产品，以及 UI 可以据何种证据呈现运行结果；不指定 SDK、IPC 或持久化结构。

设计状态：Proposed（2026-09-22）；继承 [ADR 0002](../decisions/0002-engine-native-and-product-shared-tools-are-distinct.md) 与 [ADR 0003](../decisions/0003-cross-engine-collaboration-is-task-scoped.md)，不新增已接受选型。实现与验证状态：当前仓库无 Adapter 或行为测试；下列 EA 场景是未来验收条件，未执行。概念及状态归属见[领域模型](../domain/README.md)、[生命周期](../domain/lifecycle-and-ownership.md)；共享授权见[共享能力](shared-capabilities.md)，协议层次见[架构](../architecture/README.md)。

## 最小接入与能力声明

<a id="ENG-01"></a>
**ENG-01 最小完整接入。** 自研 Engine Adapter 应能声明版本和运行条件，创建绑定该 Engine 的 Session，提交一次输入，关联输入与 Execution，输出至少一种可呈现结果或明确错误，并报告会话关闭和取消请求的处理结果（可以明确不支持原生关闭／取消，而不能虚报成功）。正常完成必须有原生完成证据；没有可核实终态时只能报告未知，不能用连接关闭推断成功。恢复、运行中介入、原生审批、工具注入、用量和子 Agent 控制可以不支持，但必须明确声明。Engine 必须仍拥有自己的 Agent Loop；仅调用 Model API 生成文本不满足完整 Harness 接入，若另行构建 Loop，该运行体才作为独立 Engine 评审。

<a id="ENG-02"></a>
**ENG-02 条件化能力。** Adapter 对每项能力报告支持性（支持／不支持／待验证）和当前可用性（可用／暂不可用／授权不足），附 Engine、Adapter 版本、执行环境、配置版本及必要原因。缺字段表示未知，不等于不支持；支持且当前不可用也不等于永久不支持。宿主在启动和条件变化时重新检查组合，UI 展示原因和可选操作。任何降级须呈现实际方式，不能通过换到更高权限环境恢复表面可用。未核实的 Engine × Workspace 组合不得标记可用。

## Session 与输入

<a id="ENG-03"></a>
**ENG-03 Session 操作。** 创建前宿主校验 Engine 可用、环境可达及必要授权；面向业务的创建和恢复同时遵循 [LIFE-ADMISSION](../domain/lifecycle-and-ownership.md#LIFE-ADMISSION)，Session 可用不替代所属 Task／参与者的执行资格。只读历史或对账不得借恢复隐式启动原生业务；恢复会自动续跑且无法约束时须报告限制。产品 Session 与原生身份的映射在确认后建立，创建响应丢失则保留待核实关联，不盲目重复创建。恢复只能面向原 Engine，并检查原生句柄、版本和原生存储是否仍有效。不支持恢复时 UI 保留产品历史，提供显式新建 Session 或 Handoff，不能称为“恢复成功”。关闭请求须说明是释放连接、结束原生会话还是删除原生状态；关闭连接不证明执行停止，删除不是默认副作用。

<a id="ENG-04"></a>
**ENG-04 输入阶段证据。** 四阶段的含义由[输入生命周期](../domain/lifecycle-and-ownership.md#LIFE-INPUT)定义；以下约束确认条件及可观察证据，并非另一套 Execution 状态机：

| 阶段 | 谁确认及前置条件 | 用户可见含义 |
| --- | --- | --- |
| 已接收 | 产品入口校验格式并记录请求标识 | 产品已收到；未承诺排队成功或 Engine 接受 |
| 已接纳 | Adapter 从 Engine 或受控执行宿主获得接纳证据；新执行输入建立 Execution，运行中介入关联现有 Execution | 执行方承担处理责任；仅在产品队列等待不算接纳 |
| 开始执行 | Adapter 获得原生开始证据，或由已核实同步调用语义证明 | Engine 已开始处理；写入套接字不足以证明 |
| 执行完成 | Adapter 获得原生终态及其结果，产品记录该证据 | 本次执行结束；不等于参与者分工完成或 Task 验收通过 |

宿主在排队校验后、实际派发前再次按 [LIFE-ADMISSION](../domain/lifecycle-and-ownership.md#LIFE-ADMISSION) 核对 Task／参与者资格和冻结状态；冻结先于派发提交时拒绝交付，不创建新 Execution。派发先于冻结时保留真实证据并请求停止，不能把原生工具或外部路径声称为已受产品强制阻断。宿主必须保留接收后被拒绝的原因；排队等待不是正在执行。原生协议只提供完成证据时，可直接记录完成并注明开始时刻未知，不伪造中间事件。输入的关联标识及幂等范围见 ENG-06。

<a id="ENG-05"></a>
**ENG-05 排队、介入和中断。** 首选草案为同一 Session 一次只执行一个输入，其余按明确队列顺序等待。运行中介入只在能力和授权允许时发送；不支持时产品须让调用者明确选择下一轮排队或拒绝，交互 UI 展示策略，自动化需预先配置，未选择时拒绝。介入成功只证明原生接纳程度，不证明模型理解。受支持的运行中介入保留独立输入／消息证据，并关联当前 Execution，不创建另一个并发 Execution；下一轮排队的输入只有获得执行方接纳后才建立新 Execution。中断请求和执行停止分别记录；不支持原生中断时报告限制，仅在执行宿主明确允许且用户授权覆盖时提供终止自有进程选项，不能伪装成原生取消。任务聚合规则见[协作契约](cross-engine-collaboration.md#COL-07)。

## 事件、审批与失败

<a id="ENG-06"></a>
**ENG-06 关联、顺序和重连。** 产品可观察事件必须关联 Engine、产品 Session、Execution（如适用）、来源和事件标识；保留可获得的原生关联标识。Adapter 生成产品事件标识和流内序号时，只保证该 Adapter 实例的一个事件流顺序，重启使用新流身份；不得据到达顺序宣称跨 Engine 的全局因果顺序。分片附所属结果和分片序号；来源无法支持稳定去重时须声明这一限制。产品按稳定事件标识去重投影，重复完成不能重复发布产物或接纳任务结果。

重连先查询执行状态或重放可用游标；有缺口则显示缺口及最后已知证据，不补造文本、工具事件或用量。不能查询或重放时，将受影响执行保持为结果未知。接纳回执也未收到时保留未决投递记录，不虚构已接纳 Execution；未决投递同样阻止任务被宣称全部停止；按 [LIFE-03](../domain/lifecycle-and-ownership.md#LIFE-03) 显式放弃协调不改变该未知事实。产品请求标识只能防止同一产品记录重复入队；除非原生协议验证了幂等处理或查询明确证明未执行，响应丢失后不得自动重发可能有副作用的输入。重试应创建可追溯的新 Execution，并先核对已发生副作用。终态记录保留来源；后到的普通事件不得重开已结束执行。互相冲突的原生终态应产生诊断和人工核实项，禁止悄悄用“最后写入胜出”改成成功。

<a id="ENG-07"></a>
**ENG-07 审批与用户输入。** Adapter 仅映射 Engine 公开的请求，保留请求标识、作用范围、关联执行、允许选项和有效期。产品回答前校验请求仍有效、回答者授权及 Engine 支持的语义；重复回答不得再次放行动作。用户拒绝、超时或 UI 退出不应被映射为同意；无回答时维持等待或按已声明策略拒绝，显示实际结果。批准记录只说明产品授权，必须等实际执行方确认，不能宣称底层限制已解除。用户输入请求与权限批准分开呈现，普通文本回复不自动扩大权限。

<a id="ENG-08"></a>
**ENG-08 错误及原生扩展。** 失败响应必须关联操作、发生层和已知副作用；至少区分：

| 结果 | 判断依据与产品行为 |
| --- | --- |
| 不支持 | 能力契约不提供该操作；禁用入口并说明替代方式 |
| 暂不可用 | 条件暂不满足；显示缺失条件，可在条件恢复后重新校验 |
| 授权不足 | 指定范围未获授权；展示所需范围，不自动提权 |
| 执行失败 | 执行方确认失败；显示错误和已发生结果，不假定无副作用 |
| 结果未知 | 缺乏足够完成或失败证据；保留核实入口，禁止自动作为成功或安全重试 |

扩展事件和命令使用 Engine 命名空间及版本，UI 只有在有对应渲染器时提供专属交互，否则显示受限提示；未知扩展不影响已知核心事件消费，但未知权限命令必须拒绝。产品协议版本不兼容时拒绝启动并说明需要的版本；Adapter 隔离第三方类型。推理、工具、原生子 Agent、用量和私有状态只映射原生公开内容，不要求导出私有上下文；缺失值保留未知，不能补零或虚构完成。

## 契约验收

使用可控假 Engine、事件回放和持久化重启夹具验证产品语义；接入真实 Engine 时，再用固定版本验证其 Adapter 映射。前者通过不能证明某个真实 Harness 支持相同能力。

| 标识 | 输入或故障注入 | 必须观察到的结果 |
| --- | --- | --- |
| <a id="EA-01"></a>EA-01 | 最小自研 Engine 提供创建、输入、结果，对关闭／取消明确回复不支持；恢复与介入不支持 | ENG-01 基本路径可用；缺失能力有明确标签，无模拟恢复 |
| <a id="EA-02"></a>EA-02 | 授权失效、环境断开、未知版本分别接入 | 能力可用性按 ENG-02 变化，不被统一折成“不支持” |
| <a id="EA-03"></a>EA-03 | 先接收、排队，再原生接纳；分别向支持及不支持 steer 的 Engine 注入运行中输入 | 阶段证据可区分；不支持时显式排队／拒绝，支持时介入关联当前 Execution 且保留独立输入证据，不增加并发执行 |
| <a id="EA-04"></a>EA-04 | 重复事件、流断线、游标缺口及相互冲突终态 | 无重复产品副作用；缺口、未知和冲突可见，无虚构全局顺序 |
| <a id="EA-05"></a>EA-05 | 输入已送达但响应丢失，原生查询也不可用 | 不自动重发；接纳或执行结果未知，核对副作用后才能显式重试 |
| <a id="EA-06"></a>EA-06 | 审批拒绝、过期、重复回答及 UI 退出 | 无默认放行，过期答案被拒，保留实际停止／等待证据 |
| <a id="EA-07"></a>EA-07 | 未提供用量、仅提供结束事件及未知扩展 | 未知值不补零，开始时间不伪造，核心消费继续且未知命令不执行 |
| <a id="EA-08"></a>EA-08 | Task 已终态但 Session 仍 open，或原生会话刚恢复；再提交新输入，同时读取历史、查询状态并接收迟到事件 | 业务请求因任务资格被拒，不产生新 Execution；获准历史读取、对账及证据记录继续，不自动重开 Task 或重绑 Session |
| <a id="EA-09"></a>EA-09 | 输入已排队，冻结分别发生在派发提交前后；同时请求委派和共享工具 | 冻结前未派发的工作不交付，委派与工具同样受资格校验；已派发工作保留接纳／未知证据并请求停止，不虚报强制阻断或立即停止 |

## 待评审与验证

同 Session 串行输入是首选提案，理由是避免跨原生上下文的交错语义；若将来支持并发，应先给出可区分执行及隔离保证。稳定请求去重的保存期限、事件保留窗口与兼容版本范围须在具体实现规格中定量确定，未确定前不能对外承诺无限恢复。真实 Engine 的原生完成、查询、取消和审批语义须按版本建立能力证据，本轮未进行第三方能力核验。
